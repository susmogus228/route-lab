# Responsive workspace correction

The user reported the interface as visibly broken in the narrow Codex browser pane. The actual initial viewport was319×672px. The Find route button had collapsed to44px wide and the map began at y881, below the first screen.

The earlier integration checks covered page overflow and working requests. They did not assert minimum button width or first-screen map visibility. This correction adds those conditions.

## Changes

- The two primary actions use equal grid columns independently of the input fields. The duplicate Open API link was removed from this row; the API navigation tab remains visible.
- The headline, metadata and controls adapt to a narrow application pane. Short scenario labels fit the select; the map heading keeps the descriptive name.
- A compact cost/steps summary sits beside the map controls. Status messages and errors remain visible in the active tab.
- Result metrics use two columns. A comparison table shows both algorithms with readable names.
- The canvas fits the available first-screen height, keeps square cells and uses the same geometry for drawing and pointer coordinates. Padding clicks do not edit cells. Resize and keyboard editing retain correct coordinates.
- Existing Python algorithms, service, HTTP adapter and recorded scientific results were preserved.

## Evidence

At319×672, each primary button is132px wide. The default map now occupies y492–660 and the cost summary is visible above it. Viewports319×672,375×812,768×1024 and1280×800 passed the geometric assertions.

The optional `tests/browser-ui.cjs` check completed **64 assertions**: viewport composition, rendered square cells, all four corner clicks at each size, keyboard editing, padding safety, reset, weighted/unreachable/singleton/thin maps, comparison, trace slider, JSON import and API200/400 responses. The Python suite passed **58 tests**. The benchmark verifier reconciled45 scenarios,90 summaries and450 timings. Seven Python source files matched the pre-change SHA-256 values byte-for-byte.

The first full Python run encountered an intermittent Windows connection-abort race when a test sent an oversized body while the server rejected its length. The test now checks rejection from the oversized Content-Length before transmitting a body, and additionally checks acceptance at exactly256KiB. The server was not changed.

An independent UI Designer returned **PASS for the reported responsive defect** after reviewing all four captures and the actual in-app view.

## Limits

The smallest pane fits the entire default grid, so its cells remain small; inspect a cell to read its cost, or use the keyboard. Precision touch editing of very large maps is not established. A full screen-reader audit and public deployment were not performed.
